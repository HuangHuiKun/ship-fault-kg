## 三、代表性的新增因果链

### 1. 电控失效影响燃烧和温度

```text
VIT 电—气转换器失效
  → 执行机构控制气压不足
  → 可变喷油定时执行不到位
  → 主机后燃严重
  → 扫气温度和排烟温度同时升高
```

最后一条用“有表现”关系而非强行作为根因。检查是对照该机出厂数据测量输入电流、输出气压和示功图；措施是专业人员更换转换器并标定。不推广原文章的固定压力临时改装。

### 2. 一台副机的故障影响共用燃油管路和另一台供电副机

```text
高压油泵出油止回阀弹簧断裂
  → 出油阀止回功能丧失
  → 气缸气体反冲进入燃油管系
  → 多台副机共用燃油总管混入气体
  → 供电副机因燃油进气停车
```

原文同时查出喷油器针阀卡在开启位置，这是回流路径的另一项条件。因此，图上的路径不能被解释成“弹簧断裂在任何构型下都必然造成另一台机组停车”。未排除的条件、设备结构和适用范围仍须随证据送入 LLM。文章内另一次启动阀故障用独立范围保存，不拼入这条链。

### 3. 排气阀机械与气动耦合

```text
闭阀空气弹簧活塞环积碳增加
  → 闭阀空气弹簧腔泄漏
  → 闭阀空气压力下降
  → 排气阀关闭不实
  → 促成排气阀落座敲击
```

对应证据包含气密性试验和密封环维护。个别机型的落阀时间不升级成所有船舶的通用限值。

### 4. 保留推测而不伪装成已证实原因

MG-800 案例更换 ADU 后恢复正常，支持故障位置判断；“复电浪涌损坏 ADU”是作者事后推断，没有现场浪涌波形。对应关系保存为 `source_hypothesis_unmeasured`，不能在增强报告中表述成已测量证实的根因。

## 四、如何保存和避免串错案例

1. 保存实际阅读的来源 ID、文件哈希和原文引句。片段阅读额外保存 `reviewed_excerpts`。
2. 助手为主语、宾语显式指定 Fault / State / Factor / Check / Action 等类型；程序检查关系允许的端点类别。
3. 同文不同故障或排查分支用不同 `scope_id` 保存。检索逐范围扩展，不跨事故拼接为已证实因果链。
4. 每条新增声明的引句必须可在原始文件中定位。片段模式还要求引句在本次明确登记的阅读范围内；只有文件中存在但没有登记为读过的文字，不能通过该门禁。
5. 同一证据范围内重复声明去重；不同来源对同一机制的支持保留各自证据。设备/实例/来源索引关系不冒称独立机理。
6. 重建 SQLite、JSONL 和待导入 Neo4j 的 JSON 快照，刷新阅读队列，再核验一致性。

专业专家复核仍为 0；所有新增声明保存助手整理和未经专家复核的标记，不应用作实船操作指令。来源引句存在不代表二手文章的机理一定正确。

## 八、查看路径与后续优先级

- `authored_statements.jsonl`：累计新增声明的主谓宾、证据和批次。
- `reviewed_sources.jsonl`：阅读范围、备注与排除原因。

- `source_complete_reading_queue.jsonl`：剩余资料的机械定位窗口；不代表助手已阅读。
- `build_report.json` / `verification_report.json`：当前规模及核验结果。
- `retrieval_smoke_examples.json`：7 个样例的实际返回证据。
- `ship_fault_kg.sqlite` / `neo4j_snapshot.json`：当前实验图谱本地存储与待发布快照。
