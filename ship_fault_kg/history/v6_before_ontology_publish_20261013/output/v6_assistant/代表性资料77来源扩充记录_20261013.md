## 1. 本轮实际完成什么

从前一轮尚待处理的 1,077 个来源中选出 77 个中文维修/机理文章，读取其中的代表性原文片段，当前聊天助手据此编写知识声明。74 个来源形成 **189 条直接知识声明**，3 个来源的所选片段暂不采纳。**全部按片段审阅登记，没有把局部阅读标成通读整篇。**

没有使用本地 3B 模型，没有调用外部模型 API。挑选窗口的程序只是资料定位辅助；实体类型、关系方向、确定性以及是否采纳均由助手在看到原文后决定。重新运行建图程序只会处理已保存的声明，不会在后台自动阅读或推理剩余资料。

这 77 个来源均来自 `ship_fault_kg_data/01_datasets/marine_diesel_RAG_corpus_All_data/All_data` 的中文文章。来源登记保留完整路径、ID、原始文件哈希；本轮没有新下载原厂手册或官方报告，也不把文章转载的手册内容当成独立取得的官方原始材料。

## 2. 筛选与审阅方法

1. 排除此前已整理的来源及 V5 已使用的来源，避免重复处理同一个来源 ID。
2. 根据标题、故障词和机理/检查词对原文窗口做机械排序，优先选择故障相关材料。筛选代码不产生知识声明。
3. 助手逐组读取原文窗口，从中选取能够独立支持机理、症状、检查或运维内容的完整语句；不强求每篇都形成新因果链。
4. 对原因假设、故障树分支、拆检发现、作者机理判断、维修结果分别记录确定性。没有阅读到最后结论时不补写最终根因。
5. 对同一机制的新证据可以保留独立来源；近似重复而没有新证据价值的段落暂不采纳。这里不是对剩余资料的全面相似度去重或全文审阅。
6. 保存显式主谓宾与类型、原文引句、适用范围和注意事项。片段模式要求声明引句位于明确登记的 `reviewed_excerpts` 内，并且能在原始来源定位。
7. 在同一证据范围内去重，按现有 12 类实体、24 类关系组装，输出 SQLite、JSONL、JSON 图快照，刷新审阅队列并核验。

有些资料只有“可检查哪些部位”，而没有足够证据证明哪个部位真正损坏。此时只生成 Check 关系，不虚构 Fault 或已确定根因；这些检查知识仍有助于后续增强诊断报告。

## 4. 新增知识的代表性例子

### 发电机机械故障传递至电气损坏

来自《某轮船舶发电机损坏故障诊断与分析》：

```text
输入端轴承保持架碎裂
  → 滚珠分布异常
  → 发电机转子下沉
  → 促成转子与定子擦碰
  → 促成定子绕组磨损
  → 增加绕组匝间或对地短路风险
```

这是原文拆检与作者机理分析支持的路径。它适合检索“机械轴承损伤为何会影响发电机绝缘”；不能把案例中的半毫米间隙作为全机型标准。

### 电控液压阀卡阻触发主机保护

来自《MANBampWMEB电喷主机MEV阀故障》：

```text
ME-V 阀驱动活塞及阀体拉伤
  → 驱动活塞卡阻
  → 无法正常响应电控指令
  → 反馈信号异常
  → 促成主机自动降速保护触发
```

同时记录“按原厂规程更换 ME-V 阀总成并验证反馈”的措施。文章中的低温间隙分析没有直接实测证明，本轮没有把它登记为已确诊的唯一起因。

### 调速反馈零位不一致造成启动超速

来自《柴油机调速系统典型故障案例分析》：

```text
燃油齿条电气零位与机械零位不一致
  → 启动实际供油量过大
  → 促成柴油机启动超速
  → 促成超速保护紧急停机
```

对应措施是修理回装后按机型程序进行零位标定。某机型没有零位联锁，不能推广成所有电子调速器都存在该缺陷。

### 不是只增加故障：新增检查和措施

本轮还补充了：

- 将滑油油样的光谱/铁谱与缸套、活塞环材料成分及拆检结果结合，检查拉缸。
- 对比污油柜油位增长与主机异常滑油消耗，检查滑油流向。
- 核查高压燃油泵滑油道通畅性及滚轮衬套配合尺寸，排除润滑供应和装配因素。
- 检查调速拉杆轴承、球形接头活动与杂质，并按规程维护。
- 按原厂工艺核查止推轴瓦接触着色与安装间隙。
- 按系泊试验方案核查船尾水域净空，减少外部水流场叠加导致超负荷的风险。

资料中运行时开曲轴箱、松开高压油接头、直接取消保护或未经批准改造等做法，没有被保存为可直接推广的操作指令。单机压力、温度、小时数和间隙保留在来源引句中，不升级成全部船型的通用阈值。
